# 16Agent・SubtaskSeparated・環境/報酬変更条件 (v3)

## 条件と元データ

- 学習run: `wh_middle2Gate_ST_16_v3_01`～`03`。trainer seedは順に1、2、3。
  PPO、各5,000万step、1 Unityプロセス内の6環境 x 各16Agent（計96体）。
- 学習時の記録は全runで `STseparated_v3`（Configハッシュ `8b1448e0...7235`）と
  `Middle_2Gate_v2`（環境Presetハッシュ `4d08f26a...ac44`）で一致する。
  各環境は40 x 47 m、棚12、ゲート2、棚Colliderあり。
- Configは `SubtaskSeparated` / `Scalar` / `LegacyScalar9`、16Agent、接触罰は各Agent -5、
  接触停止1秒、壁接触罰-1、棚到達報酬15、出口完了報酬20、最大15,000 step。
  フェロモン分泌量1、100 FixedUpdateごとに5%蒸発、Scalarフェロモン報酬倍率0.0002。
- 推論は各runの最終ONNXを使用。1環境 x 16Agent、決定的推論、固定シミュレーション時間300秒、
  trial seed 1～5の各5試行。全15試行が `simulation_duration_target` で終了。
  3件の `test_experiment.json` はいずれも学習時Config・環境Presetとのハッシュ一致を記録する。
- 元データは各 `results/wh_middle2Gate_ST_16_v3_{01,02,03}/` の `configuration.yaml`、
  `unity_experiment.json`、`test_experiment.json`、`logTest.csv`、`logTest_summary.csv`、
  `WarehouseRobot/events.out.tfevents*`、`pheromone_trials/`。`results/` はGit管理外。

  これはログ上の出現状況であり、タイムアウト率を直接表すものではない。

## 比較の扱い・解釈

- `wh_middle2Gate_ST_16_v2_*` は、今回意図したv3条件ではなく `STseparated_v2` / `Middle_2Gate_v1`
  で学習されたことを `unity_experiment.json` で確認した。**v3の反復結果には含めない**。
  v2の記録は削除せず、設定指定ミスがあったrunとして保持する。
- 先行の `wh_middle2Gate_ST_16_v1_01` / `_02` は旧環境Presetと旧報酬条件。
  v3ではゲート幅、環境寸法・通路、棚/出口/壁報酬など複数の条件が変わっている。
  搬送数の増減を一つの変更やフェロモンの効果へ帰属できない。
- 旧環境のゲート幅10m・スポーン間隔1.5mでは2ゲート合計14スロットだった。
  v3の幅15mなら同じ計算で18スロットとなり、16体分の総数は足りる。
  ただし入口のランダム割当や接触位置の記録がないため、スポーン直後の重なりが
  実際に減ったかどうかは未検証。
- 今回は同一Configでtrainer seed間に搬送量と接触傾向の差が出た。
  試行seedは5件、学習seedは3件であり、安全性や汎化性能の優劣はまだ断定できない。

## 次の検証

1. 接触の場所・時刻、スポーン直後の接触、停止時間を分けて記録し、混雑原因を切り分ける。
2. v3と同じ環境・Agent数・接触ルール・報酬でフェロモンなし条件を作り、同じtrainer/test seed集合で比較する。
3. 必要なら棚接触の多さと目的棚以外への接触を映像・軌跡と突き合わせる。
